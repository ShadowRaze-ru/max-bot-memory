# Запоминалка

Фронтенд мини-приложения MAX для работы с учебными карточками. Проект использует Vue 3, TypeScript, Vite, Pinia и KaTeX. Исходный код бэкенда в этом репозитории отсутствует.

## Требования

- Node.js 24 LTS и npm.
- Для работы с серверными данными — доступ к совместимому API и его ключ приложения.

## Локальный запуск

```bash
git clone https://github.com/ShadowRaze-ru/max-bot-memory.git
cd max-bot-memory
npm ci
npm run dev
```

Откройте адрес из вывода Vite: по умолчанию это <http://127.0.0.1:5173/>. Для остановки нажмите `Ctrl+C`.

Без дополнительной настройки приложение работает с демонстрационными данными: изменения и прогресс сохраняются в `localStorage` текущего браузера, а не на сервере. Если у вас уже есть `.env.local` с `VITE_USE_API=true`, установите там `VITE_USE_API=false` и перезапустите сервер для перехода в демонстрационный режим.

## Подключение API при разработке

1. Создайте `.env.local` на основе `.env.example`:

   ```bash
   cp .env.example .env.local
   ```

   В Windows PowerShell вместо этой команды можно использовать `Copy-Item .env.example .env.local`.

2. Укажите в `.env.local` значения, полученные от команды бэкенда:

   ```dotenv
   VITE_USE_API=true
   API_TARGET=https://your-api-host.example
   API_APP_KEY=your-app-key
   API_DEV_USER_ID=12345678
   ```

   `API_TARGET` — адрес сервера без `/api/v1`; `API_APP_KEY` — ключ приложения; `API_DEV_USER_ID` — числовой ID тестового пользователя. Примерные значения необходимо заменить на действительные.

3. Перезапустите `npm run dev`. Vite отправляет запросы через локальный прокси `/backend-api`; сервер API должен быть доступен с машины разработчика и иметь действительный HTTPS-сертификат.

**Не публикуйте `.env.local` и не используйте секретный ключ:** настройки API, в том числе `API_APP_KEY`, могут попасть в код, доступный браузеру. Файл `.env.local` исключён из Git, но это не защищает ключ, встроенный в сборку.

## Проверки и сборка

```bash
npm test             # тесты
npm run typecheck    # проверка типов
npm run build        # проверка типов и production-сборка в dist/
npm run preview      # локальный просмотр собранной версии
```

`npm run preview` запускают после сборки; адрес выводится в терминале. Он не заменяет production-сервер.

Режим работы выбирается **во время сборки** из переменных окружения. Чтобы собрать API-версию, задайте `VITE_USE_API=true`, `API_TARGET` и `API_APP_KEY` в `.env.local` до запуска `npm run build`. В опубликованной сборке запросы идут напрямую к API, поэтому бэкенд должен поддерживать CORS для адреса сайта и иметь действительный HTTPS-сертификат. В MAX используется ID пользователя из данных запуска; необязательный `API_DEV_USER_ID` в сборке служит резервным тестовым ID вне MAX. Не добавляйте его в production-сборку, если такой режим не нужен.

В API-режиме бэкенд отвечает за прогресс и интервальное повторение. При отсутствии карточек по расписанию доступен тренировочный повтор без записи оценок в серверный прогресс.
