# Запоминалка

Vue 3 + Vite + TypeScript + Pinia + KaTeX. Данные пока моковые, прогресс хранится в localStorage.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # SM-2 и безопасный рендер формул
npm run typecheck
```

## Что уже есть
- `src/lib/sm2.ts` — расчёт SM-2 (чистая функция, потом переедет на сервер) + тесты
- `src/lib/katex.ts` — текст + `$inline$` / `$$display$$`, экранирование HTML, `throwOnError: false`
- `StudyCard.vue` — карточка по макету (вопрос → «Показать ответ» → ответ с пояснением)
- Экран сессии: очередь, «Снова» возвращает карточку в конец (как «< 1 мин» на макете), подписи интервалов под кнопками,
  экран итогов с конфетти, стрик (сессия от 5 карточек)
- Главная: стрик, «К повторению сегодня», список колод
- Библиотека: колоды с прогрессом, API CRUD колод и карточек, предпросмотр KaTeX
- Каталог общих колод без поиска; единая нижняя навигация доступна на всех экранах
- Каталог и серверная библиотека колод в API-режиме: просмотр, добавление, CRUD колод и карточек
- Профиль, дневной лимит новых карточек, пользовательские настройки и добавление колод по share-коду
- Клавиатура на десктопе: Пробел или Enter — перевернуть, 1–4 — оценка

Локально по умолчанию используются моковые данные и `localStorage`. API-клиент и dev-proxy подключают backend в режиме разработки. В текущем workspace `.env.local` настроен на тестовый backend и тестовый ID `12345678`; не коммитьте этот файл. Для собственной настройки:

1. Скопируйте `.env.example` в `.env.local`.
2. Заполните `API_TARGET`, `API_APP_KEY` и `API_DEV_USER_ID` тестового пользователя.
3. Установите `VITE_USE_API=true` и перезапустите Vite.

Vite проксирует `/backend-api` и добавляет `X-App-Key` на серверной стороне dev-сервера; ключ не встраивается в клиентский bundle. При первом запросе синхронизируется тестовый пользователь. Проверены чтение и обновление профиля, каталог и библиотека; в тестовой библиотеке есть серверная колода `676`.

Production API-режим включается через `VITE_USE_API=true` при сборке и использует `API_TARGET` и `API_APP_KEY` из `.env.local`. Тестовый ключ намеренно встраивается в публичный bundle — используйте только ключ, который бэкендер выдал для проверки с фронтенда. В MAX берётся ID пользователя из MAX; вне MAX используется `API_DEV_USER_ID` как тестовый профиль. Backend должен иметь действующий HTTPS-сертификат и разрешить CORS с домена Hosting. Текущий API принимает ID пользователя в `X-VK-User-ID`/`vk_user_id`. В API-режиме обучение создаётся через серверные `/study/sessions` и `/reviews`; очередь, оценки FSRS, дневные квоты и серия приходят с сервера. В mock-режиме остаётся локальная SM-2-очередь.

MAX SDK загружается до приложения и считывает параметры запуска из фрагмента URL. После этого фрагмент с параметрами MAX заменяется на `#/`, чтобы hash-маршрутизатор открыл главную страницу; внутренние маршруты приложения сохраняются.

## Дизайн
Экраны главной, занятия, библиотеки и редакторов сверяются с актуальным макетом `FlashCardsSferumDone.pen` (артборд 390×844; токены `#0077FF`, фон `#F2F3F5`, Inter). Формулы LaTeX можно вставлять в вопрос и ответ с позиции курсора; доступны предпросмотр, дробь, корень, степень и отдельная формула. Для изображения вопроса указывается HTTPS-ссылка. Загрузка файла изображения, аудио и ИИ-создание колод пока не подключены. Настройка показа подсказок работает.

В API-режиме при отсутствии карточек по расписанию можно пройти колоду в тренировочном повторе. Такой повтор не отправляет оценки на сервер и не меняет FSRS, дневные квоты или серию.

## Отличие от ТЗ
Кнопки 1–4 мапятся на оценки SM-2 как 1→1, 2→3, 3→4, 4→5 (см. комментарий в `sm2.ts`).
Иначе «Легко» никогда не повышало бы коэффициент лёгкости.
